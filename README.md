# Цифровой дизайнер презентаций

Берёт любую `.pptx`-презентацию как дизайн-систему и переносит на неё новый контент в том же визуальном языке: без ручной вёрстки и без слайдов-картинок. На выходе редактируемая колода.

```
шаблон + бриф  →  дизайн-система  →  три варианта колоды  →  аудит  →  .pptx / .html / .pdf
```

Кейс «Цифровой дизайнер презентаций», ЛЦТ 2026 (VK Tech). Подробности: [ARCHITECTURE.md](ARCHITECTURE.md), [MODELS.md](MODELS.md), [AUDIT.md](AUDIT.md), [PRODUCT.md](PRODUCT.md).

## Что умеет

- **Разбирает шаблон, а не запоминает его.** Палитра, типографическая шкала, макеты со слотами и их вместимость выводятся из самого файла — на шаблоне, которого не видели, работает так же (это проверяет `evals/test_unseen_template.py`).
- **Пишет колоду по брифу**: план → тексты слайдов, где заголовок — вывод, а не тема; речь спикера под длину выступления; 10–15 слайдов, генерация ≤ 5 минут.
- **Рисует графики, диаграммы и пиктограммы** настоящими объектами PowerPoint: график с данными из брифа, процесс, таймлайн, цикл, иерархия, сетка иконок.
- **Три варианта вёрстки** одной колоды — сжато, стандарт, подробно: не косметика, а другие равноценные дизайны шаблона для тех же слайдов.
- **Аудит с двумя видами проверок** — 26 детерминированных (правила по данным слайда, всегда) и 10 модельных (VLM смотрит на картинку, по кнопке). Исправимые чинятся по галочке.
- **Экспорт в `.pptx`** (только нативные объекты), **`.html`** (один файл) и **`.pdf`**.
- Промпты и параметры моделей лежат отдельными версионируемыми файлами в `skills/`.

## Быстрый старт

Нужны Node 22+, pnpm 9+, Python 3.12+ и [uv](https://docs.astral.sh/uv/).

```bash
git clone <repo> && cd project-preza
make setup      # ставит зависимости и создаёт .env из .env.example
# впишите INFERENCE_API_KEY в .env
make start      # API на :8000, веб на :3000 (или на ближайшем свободном порту)
```

Без `make`: `pnpm install && uv sync && cp .env.example .env && pnpm start`.

**Одним конфиг-файлом (Docker):**

```bash
cp .env.example .env   # впишите INFERENCE_API_KEY
docker compose up --build
```

Откройте <http://localhost:3000>. Compose поднимает сервер (с LibreOffice) и веб; данные хранятся в томе `preza-data`.

`make help` показывает остальные команды: `make test`, `make lint`, `make submission` (9 колод для сдачи), `make skills-lock`.

## Настройки модели

Кнопка «⚙ Настройки модели» внизу слева: провайдер (OpenRouter, инференс VK, Ollama или LM Studio локально, любой OpenAI-совместимый сервер), адрес, ключ, модель для всех шагов, отдельная модель для проверки по картинкам, своя модель для отдельного шага, режим «только моя модель», таймаут. «Проверить подключение» делает один тестовый вызов с тем, что на экране, «Список» подгружает модели сервера. Сохранённое действует со следующего запроса и лежит в `data/inference.json`; ключ в браузер не возвращается. Значения из `.env` и `skills/` — умолчания, пока в настройках пусто.

## Хранилище S3

Без него **ничего не сохраняется**: чаты и готовые презентации живут только на странице, приложение предупреждает об этом плашкой сверху и вопросом при закрытии вкладки. В «⚙ Настройки модели» ниже — раздел «Хранилище S3» (Amazon, Yandex Object Storage, MinIO, R2 и другие S3-совместимые): адрес, бакет, регион, ключи, папка. После подключения каждая готовая генерация (запрос и три варианта с аудитом) и загруженные шаблоны кладутся в бакет; список сохранённого показан слева («Сохранено в S3»), шаблоны возвращаются после перезапуска. Секретный ключ лежит в `data/storage.json` (только владелец) и в браузер не возвращается. Сохранение идёт в фоне и не удлиняет генерацию: она по-прежнему укладывается в 5 минут.

## Переменные окружения

Все — в `.env` (образец — `.env.example`).

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `INFERENCE_API_KEY` | — | ключ inference API (OpenRouter на отборе, VK на этапе топ-10); без него генерация недоступна |
| `INFERENCE_API_BASE` | `https://openrouter.ai/api/v1` | любой OpenAI-совместимый адрес |
| `INFERENCE_REQUEST_TIMEOUT` | `270` | секунд на один вызов модели |
| `INFERENCE_MAX_RETRIES` | `1` | повторов при обрыве соединения |
| `UNSPLASH_ACCESS_KEY` | — | фото Unsplash; без ключа фото ищутся в Openverse и Wikimedia Commons |
| `SOFFICE_PATH` | из `PATH` | путь к LibreOffice: нужен только для векторного PDF и серверных превью |
| `SERVER_PORT` / `WEB_PORT` | `8000` / `3000` | порты `make start` |
| `NEXT_PUBLIC_API_URL` | `http://localhost:8000` | где браузер ищет API |

## Как пользоваться

1. Опишите презентацию и ответьте на короткие вопросы: длина выступления, число слайдов, подача, подробность. Можно приложить материалы (репозиторий, документы, историю команды) или брендбук.
2. Выберите шаблон из библиотеки или загрузите свой `.pptx` (или оставьте «подобрать автоматически»). Можно просмотреть и поправить план до генерации.
3. Получите три варианта колоды с оценкой длины речи. Под колодой панель аудита: отметьте находки и нажмите «Исправить выбранное» (есть «Отменить»), или запустите «Проверить смысл и факты».
4. Скачайте `.pptx`, `.html` или `.pdf`.

Страница `/generation` наглядно показывает, как устроена генерация: этапы, бюджет 5 минут, цепочку моделей и список проверок.

## Ограничения

- **Модели.** Нужен доступ к inference API; без ключа работает только разбор шаблона, вёрстка и аудит уже готовых колод.
- **Диаграммы вместо SmartArt.** Диаграммы — группы обычных фигур (правятся как любые), не настоящий SmartArt. SmartArt из шаблона сохраняется, но не переписывается.
- **Графики только из данных брифа.** Чисел, которых в брифе нет, модель рисовать не вправе: график тогда не строится.
- **Текст не редактируется в превью.** Правки — в скачанном `.pptx`.
- **PDF без LibreOffice** рисуется браузером картинками страниц (внешне тот же, но без выделяемого текста); с LibreOffice — векторный.
- **Не проверялось в самом PowerPoint.** Структура файла проверяется `export.validate`, вид — рендером в браузере; открыть итоговые файлы в PowerPoint стоит перед показом.
- **Нужен свободный порт 8000** для API (веб сам уходит на ближайший свободный).
- **Экзотика OOXML** (встроенное видео, макросы, SmartArt) не переписывается: остаётся как есть или пропускается с пометкой, но не роняет разбор. Файл шаблона внутри бренд-пакета — до 100 МБ.

## Структура репозитория

| Путь | Что здесь |
| --- | --- |
| `apps/web` | Next.js: чат, выбор шаблона, просмотр вариантов, панель аудита, экспорт |
| `apps/server` | FastAPI: оркестрация пайплайна, API |
| `packages/parser` | `.pptx` → IR |
| `packages/design_system` | IR → палитра, шкала размеров, макеты со слотами |
| `packages/generator` | бриф → план → контент слайдов |
| `packages/layout` | контент → слайды шаблона, три варианта |
| `packages/audit` | проверки, исправления, каталог |
| `packages/export` | IR → `.pptx`, `.pdf`; графики, диаграммы, пиктограммы; проверка файла |
| `packages/ingest`, `brand`, `images` | материалы задачи → фактлист; бренд-пакеты; фото по теме |
| `packages/inference` | клиент моделей, запасные модели, версии скиллов |
| `packages/ir_schema` | общий контракт (IR) |
| `skills/` | промпты и конфиги агентов, версии, `skills.lock.json` |
| `evals/` | тесты на шаблонах, в том числе собранных с нуля; сборка колод для сдачи |
| `scripts/` | запуск (`dev.sh`), фиксация версий скиллов |

## Проверки

```bash
make check     # ruff + tsc + все тесты
```

Тесты пакетов лежат рядом с кодом; `evals/` — сквозные, на реальных и синтетических шаблонах. CI-конфиг — `ci/github-actions-ci.yml` (перенесите в `.github/workflows/`).
