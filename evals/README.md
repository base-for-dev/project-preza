# Evals

Тесты пайплайна на реальных шаблонах — не unit-тесты для галочки. Главный риск, который проект обязан закрыть, — генерализация: работает ли пайплайн на шаблоне, которого он раньше не видел, без изменения кода.

```
evals/
  templates/   — примеры .pptx-шаблонов (3 выданных + любые team-собранные для теста на генерализацию)
  fixtures/    — входы бриф/контент-пакет, парные с ожидаемыми снапшотами IR
```

## Что здесь должно быть

- Round-trip тест: template.pptx → IR → template.pptx, диффом со сравнением с оригиналом.
- Тест генерации: один контент-пакет × N шаблонов → колоды, сверка с детерминированными проверками из `AUDIT.md`.
- Тест на отложенном шаблоне: шаблон, никогда не использовавшийся в разработке, прогоняется end-to-end. Именно этот тест реально доказывает п.5/п.11 ТЗ (отсутствие хардкода).

Запуск: `uv run pytest evals`.
