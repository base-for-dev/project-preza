# preza-layout

Контент + токены -> собранный IR слайда (подбор паттерна, укладка, ось 3 вариантов).

Используется `apps/server`. См. `ARCHITECTURE.md` в корне репозитория — как этот пакет встроен в пайплайн.

## `compose_deck`

```python
def compose_deck(deck_content: DeckContent, template_deck: Deck, variant: Variant) -> Deck: ...
```

Чистая Python-композиция, без LLM-вызова: outline/content уже сгенерированы,
здесь только укладка. Для каждого `SlideContent` ищется реальный `Slide` в
`template_deck` с тем же `layout_name == role` (циклически, если ролей-инстансов
несколько), его фигуры глубоко копируются как структурная база (геометрия,
шрифты, заливки, z-order сохраняются), и переписывается только содержимое
текстовых плейсхолдеров.

Сопоставление фигур с контентом — исключительно по `ShapeBase.placeholder_type`
(`TITLE`/`CENTER_TITLE` -> заголовок, `BODY`/`SUBTITLE`/`OBJECT` -> буллеты/тело,
`Table` -> таблица), никогда по `name` или позиции — тот же принцип, что и в
`design_system/patterns.py`, иначе не обобщается на незнакомый шаблон. Если у
паттерна нет явного body-плейсхолдера, контент уходит в крупнейшую по площади
нетайтловую `TextBoxShape`/`AutoShape`. `Picture` и `PassthroughShape` не
трогаются никогда. Если `role` не находит соответствия в `template_deck`,
`compose_deck` бросает `ValueError` с именем роли.

Ось вариативности — два независимых параметра одного прохода
(`Variant = "compact" | "standard" | "detailed"`, см. `PRODUCT.md`):

- **Плотность текста.** `compact` — первые 3 пункта, без `body`; `standard` —
  все пункты (не больше 6), `body` только если у паттерна есть отдельный слот
  под него; `detailed` — все пункты и `body` последним абзацем.
- **Дизайн слайда.** Для каждого слайда есть равноценные слайды шаблона —
  те же слоты картинки и таблицы, где помещается тот же текст (список из
  четырёх пунктов может лечь на карточки или на текстовый макет).
  `standard` берёт исходный, `compact` и `detailed` сдвигаются на следующие
  (`alternate_slides`), так что три варианта — три разных набора собственных
  дизайнов шаблона, а не три копии одного. Обложки и разделители меняются
  только внутри своего семейства макетов.

Заголовок идентичен во всех трёх вариантах; таблица переезжает вместе со слайдом. Таблица обрезается до
`AUDIT.md`'s лимитов (≤7 строк, ≤5 колонок); если `SlideContent.table is None`,
таблица шаблона остаётся как есть. Стиль подставляемого текста берётся из
первого существующего run'а того же плейсхолдера (шрифт, размер, цвет,
bold/italic/underline) — если run'ов не было, стилевые поля остаются `None`,
экспорт применит плейсхолдер-дефолты.

`template_deck` не мутируется — `compose_deck` возвращает новый `Deck`.

Тесты: `tests/test_compose.py` (синтетические фикстуры, без HTTP). Живая
демонстрация на реальном шаблоне: `evals/demo_layout.py` — без LLM-вызова,
всегда можно запускать (`uv run python evals/demo_layout.py`).

## Графики и диаграммы (`visuals.py`)

Если автор контента задал слайду `chart` или `diagram`, `place_visual` рисует
его на месте фото-рамки слайда, а если её нет — на месте текстовой области
(в обоих случаях с небольшим отступом); шрифт и размер берутся из шаблона.
Собственный график шаблона в приоритете: если он есть, ему подставляются данные
и второй не рисуется. Слайду, где визуалу негде лечь, диаграмма превращается
в обычные пункты (`without_homeless_visual`), а график отбрасывается — контент
не пропадает молча. Тесты: `tests/test_visual_slots.py`.
